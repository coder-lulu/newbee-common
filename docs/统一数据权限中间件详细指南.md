# 统一数据权限中间件详细指南

## 更新说明
- 2024-11-24：重写文档以匹配 `common/middleware/dataperm` 最新实现，澄清 Casbin 集成、规则引擎、字段掩码与超级管理员旁路等行为。

## 1. 概览
`UnifiedDataPermPlugin` 是统一中间件链中优先级 25 的插件，位于认证、租户、RBAC 之后执行。它依赖 Casbin 提供接口级许可结果，再通过内部规则引擎、上下文管理器和字段掩码处理器构建细粒度的数据访问约束。核心能力包括：
- **Casbin 结合数据范围**：调用 `CasbinProvider.CheckPermissionWithRoles` 判定 `resource + action`，并提取命中的规则集合。
- **动态规则生成**：`PermissionRuleEngine` 基于模板和角色信息生成 `DataScopeRule`，自动区分全部/部门/个人等范围。
- **字段级防护**：`FieldMaskProcessor` 根据敏感度与规则配置执行部分遮罩、全遮罩、哈希或加密标识。
- **上下文注入与传播**：通过 `EnhancedContextManager` 将规则、字段掩码、SQL 过滤条件写入请求上下文，与 ent hooks (`entctx/datapermctx`) 配合生效。
- **超级管理员旁路**：检测角色中包含 `superadmin` 时直接赋予 `DataPermAll`，并写入审计标签。
- **Redis 复用**：可选的 Redis 客户端用于缓存生成的规则模板，降低 Casbin 重复查询开销。

## 2. 组件结构
```go
// 精简版本，源自 common/middleware/dataperm/unified_plugin.go
type UnifiedDataPermPlugin struct {
    core           *framework.CoreServices
    config         *framework.DataPermConfig
    casbinProvider CasbinProvider
    ruleEngine     *PermissionRuleEngine
    contextManager *EnhancedContextManager
    logger         *logging.MiddlewareLogger

    ruleCache map[string]*DataScopeRule
    checkCount    int64
    cacheHitCount int64
    avgResponseTimeMs atomic.Uint64
}
```

### 2.1 PermissionRuleEngine
- 初始化时加载默认规则模板并可接受 Redis 缓存（`RedisClientAdapter`）。
- `GenerateDataRules` 会根据用户上下文、Casbin 返回的规则 ID、角色和租户信息合成一组 `DataScopeRule`：
  - 若存在模板命中，生成对应 SQL 条件、字段可见性与掩码配置。
  - 若无命中，则依据角色回退到默认策略，再无结果时创建最严格规则（仅本人数据）。
- 规则结果以 `SERVICE:RESOURCE:ACTION` 为键缓存 15 分钟。

### 2.2 EnhancedContextManager
- `SetEnhancedPermissions` 把 `DataScopeRule` 列表、字段掩码与 SQL 条件写入请求上下文，并同步 `keys.DataPermContextKey` 与 ent 的 `datapermctx`。
- 提供 `SetDefaultPermissions` / `SetStrictPermissions` 以便在 Casbin 或规则生成失败时做保护性降级。
- 暴露 `GetDataRules`、`GetFieldMasks`、`GetSQLFilters` 等辅助方法供业务或 hooks 查询。

### 2.3 FieldMaskProcessor
- 预置手机号、邮箱、证件号等敏感字段档位以及 `partial_phone`、`hash`、`encrypt` 等策略。
- 在规则阶段完成配置后，响应封装器或下游处理可据此对字段进行掩码。

## 3. 配置项
`framework.DataPermConfig` 与 `UnifiedDataPermConfig` 的常用字段如下：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | bool | `false` | 是否启用统一数据权限插件 |
| `skipPaths` | []string | - | 前缀匹配跳过的数据权限路径 |
| `casbinEnabled` | bool | `true` | 是否依赖 Casbin 检查（必须为真） |
| `coreRpcEndpoint` | string | `127.0.0.1:8080` | 历史字段，当前由服务层提供 RPC，不直接使用 |
| `unified.engine.templatesEnabled` | bool | `true` | 是否启用模板驱动规则生成 |
| `unified.fieldMask.enabled` | bool | `true` | 是否启用字段掩码处理 |
| `unified.interceptor.strictMode` | bool | `true` | 无权限上下文时是否强制拒绝 |
| `unified.performance.cacheEnabled` | bool | `true` | 是否开启规则缓存 |

配置示例（摘自 `unified-io/api/etc/io.yaml`）：
```yaml
middleware:
  dataPerm:
    enabled: true
    casbinEnabled: true
    skipPaths:
      - /init/database
    unified:
      engine:
        templatesEnabled: true
      fieldMask:
        enabled: true
      performance:
        cacheEnabled: true
        cacheExpiry: 15
```

## 4. 请求处理流程
1. **跳过检查**：`shouldSkip` 对照配置决定是否绕过数据权限。
2. **权限主体定位**：从 `ContextManager` 读取用户、租户、角色，并保留原始租户信息以供审计。
3. **超级管理员旁路**：含 `superadmin` 角色时注入 `DataPermAll`，并在审计元数据中追加 `dataperm_bypass` 标签。
4. **Casbin 校验**：通过 `CheckPermissionWithRoles` 获取允许状态和命中的 Casbin 规则 ID；若被拒绝直接返回 HTTP 403。
5. **规则生成**：将用户上下文与 Casbin 结果交给 `PermissionRuleEngine.GenerateDataRules`，可使用 Redis 缓存。
6. **上下文注入**：`EnhancedContextManager.SetEnhancedPermissions` 将规则写入上下文，并附带字段掩码、SQL 过滤列表、数据范围枚举。
7. **附加审计信息**：插件在上下文中追加 `dataperm_*` 标签，供审计写入器读取。
8. **统计更新**：`updateStats` 维护检查次数与平均耗时，用于后续监控。

## 5. 集成步骤
- **CasbinProvider**：由服务在 `integration.Setup` 时通过 `DataPermCasbinProvider` 注入，通常是 Core RPC 侧的 `RpcCasbinRuleQuerier`。
- **ServiceContext**：确保 `ContextManager`、Redis 客户端以及 `TenantInfoProvider` 已初始化，以支持租户信息缓存与钩子。
- **统一入口**：
```go
result, err := integration.Setup(&integration.Config{
    Redis:                  redisClient,
    JWTSecret:              jwtSecret,
    Mode:                   integration.Production,
    ApiResourceProvider:    svc.NewApiProvider(),
    AuditWriter:            audit.NewBuiltinAuditWriter(svc),
    TenantInfoProvider:     svc.NewTenantProvider(),
    RbacProvider:           svc,               // 可选
    DataPermCasbinProvider: svc.CasbinQuerier, // 必须
    Middleware:             &cfg.Middleware,
})
```
- **Ent Hook 协同**：API 层产生的上下文会在 ORM 层通过 `datapermctx` 自动拦截并注入 SQL 条件（需要启用统一 Hook）。

## 6. 常见扩展
- **自定义模板**：将自定义 JSON 模板写入配置或下发到 Redis，再由 `PermissionRuleEngine` 动态加载。
- **字段策略下沉**：业务可在 `PermissionContext.FieldMasks` 中追加自定义字段，搭配响应封装器完成脱敏。
- **监控指标**：利用插件暴露的统计字段或在 `ruleEngine` 外层包裹指标，监控缓存命中与耗时。
- **链路审计**：读取上下文的 `keys.AuditMetadataKey`，把数据权限决策结果附加到审计日志。

## 7. 故障排查
| 现象 | 可能原因 | 处理建议 |
|------|----------|----------|
| 请求直接返回 403 | Casbin 拒绝或缺少 `DataPermCasbinProvider` | 检查 Casbin 规则、确认 Integration 配置正确 |
| SQL 未附带数据范围 | 未启用统一 Hook 或上下文被替换 | 确认 ORM 初始化 `hooks.QuickSetup`，并检查中途是否创建新 context |
| 字段掩码失效 | 自定义响应未读取 `PermissionContext.FieldMasks` | 在响应包装器中调用 `FieldMaskProcessor.ProcessFieldMasks` |
| Redis 报错后全部放行 | 插件检测到 Redis 失败走降级 | 部署侧需要恢复 Redis 或降低 `cacheEnabled` 依赖 |
| 超级管理员仍受限 | 角色编码未包含 `superadmin` 或上下文未写入 | 确认认证链路是否将角色写入 `ContextManager` |

## 8. 验证建议
- 使用普通用户与 `superadmin` 分别调用同一接口，比较 `AuditMetadata` 中 `dataperm_bypass` 标记和 SQL 过滤结果。
- 模拟 Redis 不可用、Casbin 拒绝、模板缺失等场景，观察是否正确回退到默认/严格权限。
- 在集成测试中读取上下文 `keys.DataPermContextKey`，确认生成的 `DataScopeRule` 与期望一致。
- 针对 `GET` 列表、`GET` 单条、`POST` 创建、`DELETE` 删除等操作执行请求，验证 `parseResourceAndAction` 生成的 `action` 是否符合 Casbin 规则命名。

通过以上说明，可确保统一数据权限中间件在各服务落地时与真实代码行为一致，并为排障与扩展提供参考。
